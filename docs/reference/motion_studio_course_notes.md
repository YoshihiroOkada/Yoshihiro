# 参考: 「How to build motion design studio with Opus 5.5（Full-course）」の要点

出典: @0xMovez（Movez）の記事。X: https://x.com/0xMovez/article/2104216919033192746 ／
同内容の Substack: https://movez.substack.com/p/how-to-build-motion-design-studio
（全文は出典を参照。ここはこのリポジトリで使うための要点メモ）

**主張:** プロンプトは映像の10%、残り90%は「ハーネス」（参照・描画エンジン・自分のフレームを見て直す仕組み）。

| # | ステップ | 要点 |
|---|---|---|
| 1 | Pixels | モデルは動画ではなくプログラムを書く。`seek(t)` で任意の瞬間を描く決定的な描画 → ヘッドレスで撮影 → ffmpeg |
| 2 | Setup | Node / ffmpeg / Python（librosa）/ Playwright。CLAUDE.md にハウスルール（下） |
| 3 | One-liner | 一文プロンプトはエンジンの試験にしかならない（アイデアを含まない） |
| 4 | Brand | 本物の素材（URL・スクショ・ロゴ・色・書体）を集めて `./assets` に。UIを想像で描き直さない |
| 5 | Reference | 参照フレーム/動画/自分の画像フォルダ → `docs/style_guide.md`（色hex・書体・ショット長・トランジション・カメラ・質感・文字の出入り）→ `docs/shotlist.md`。参照の「文法」だけ取り、中身は取らない |
| 6 | Spec | 雰囲気ではなく状態の一覧を書く。拍のグリッドに状態を載せ、コードの前に見せる |
| 7 | Engine | `index.html` + `render.mjs`（60fps、サブフレーム4枚を混ぜてモーションブラー、libx264 crf16 yuv420p） |
| 8 | Springs | 閉形式のスプリング。目標が何度も変わる値は「変化ごとにスプリングを足す」。文字はオーバーシュート無し |
| 9 | Sound | 曲があれば測る（`beats.py` → `beats.json`: bpm / beats / downbeats / hits）。無ければコードで合成 |
| 10 | Overnight | 監督の指示書: 一行の企画・参照・道具と鍵・キャラ設定・ビートシート（最初の2秒がフック、3〜5秒ごとに新しい見せ場）・文字の出し方・工程のゲート・批評ループ・納品物 |
| 11 | Critique | コンタクトシート / ストリップ / **360px 幅のスマホテスト** / ループ確認 / 決定性（2回レンダーして同じハッシュ）。7項目を10点満点で採点、最悪の3つを時刻付きで → 直す → 全部8点以上まで |
| 12 | Ship | 1つのタイムラインから 9:16・1:1・16:9（切り抜きではなく再構成）。スキル化 |

**記事の CLAUDE.md（ハウスルール）の要点**
- 描画は時間の純関数。CSSトランジション/タイマー/フレーム間の状態禁止。乱数はシード固定（`Math.random` 禁止）
- 禁止の定番: 中央タイトル＋グラデーション、全部フェードイン、隅のラベルと枠、UIのグロー、ありがちなパーティクル
- 表示用書体1つ＋UI書体1つ、アクセント1色。**2〜4秒ごとに新しいことが起きる**
- 音: 曲が無ければコードで合成。ヒットは測った拍グリッドに。**ラウドネス -14 LUFS**
- 見せる前のループ: 拍ごとのコンタクトシートを見る → 採点（最初2秒のフック・スマホでの読みやすさ・動きの質・変化・ブランドの正確さ・音の同期）→ 最悪3つを直す → 全部8点以上まで

**批評で特に探すもの:** 入れ替え時の文字の重なり、イージングせず滑るだけの動き、隅のラベルと枠、中央＋グラデーションのショット、拡大でぼけた文字、何も起きない拍、ループの継ぎ目のカクつき。
